# 12 · 安装教程（源码开发版 · 从零部署）

> 本版本是**源码开发版**：包含前端源码（`frontend/`），面向二次开发。部署前需要完成一次构建（PHP 依赖 + 前端产物）；构建完成后，日常部署与升级不再需要 Node。
>
> 只想直接使用后台、不做二开？请使用 **Linc-Admin-Ready（开箱即用版）**——依赖与前端已内置，上传即装，教程见其 `docs/12-安装教程-从零开始.md`。两版本功能与数据库完全一致。

## 两种部署路径

| 路径 | 适合 | 流程 |
| --- | --- | --- |
| A. 本地构建后上传（推荐） | 开发机在本机 | 本机构建 → 上传含产物的完整目录 → 安装向导 |
| B. 服务器上直接构建 | 服务器装了 Composer 与 Node | clone 到服务器 → 服务器构建 → 安装向导 |

无论哪条路径，之后都走相同的**站点配置 + 安装向导**（第 4、5 步）。

## 第 1 步 · 环境准备

**本机 / 服务器通用要求**：

- PHP ≥ 8.0（扩展 `pdo_mysql`、`zlib`），含 CLI 与 FPM 两种形态；
- Composer 2（[getcomposer.org](https://getcomposer.org/download/)）；
- Node.js 22+ 与 npm（[nodejs.org](https://nodejs.org/)）；
- MySQL ≥ 5.7。

```bash
# 验证工具链
php -v && composer -V && node -v && npm -v
```

**云服务器**（路径 B 需要；路径 A 只需最终能跑 PHP + MySQL 的服务器）：购买 2 核 4G 起、放行 22/80/443 端口，推荐安装宝塔面板图形化管理 PHP / MySQL / Nginx（详见《06 配置与部署》）。

## 第 2 步 · 获取源码并构建

```bash
git clone https://github.com/<你的用户名>/<你的仓库>.git
cd <仓库>/Linc-Admin-Dev

# 1) PHP 依赖 → 生成 vendor/
composer install --no-interaction --optimize-autoloader

# 2) 前端依赖与构建 → 生成 frontend/dist/
cd frontend && npm ci && npm run build && cd ..

# 3) 前端产物部署到 public/（Vite 构建不写入 public）
cp -r frontend/dist/* public/        # Windows: 复制 dist 内全部文件到 public/
```

> 构建产物（`vendor/`、`public/assets/`、`public/index.html`）被 `.gitignore` 排除在仓库之外——这就是本版本需要这一步的原因。以后改了前端只需重跑第 2 步的 npm 部分。

## 第 3 步 · 上传 / 就位

- **路径 A（本地构建）**：把包含 `vendor/` 与已更新 `public/` 的整个目录上传到服务器，如 `/www/wwwroot/Linc-Admin-Dev`（宝塔文件管理上传 ZIP 解压，或 `scp -r`）；
- **路径 B（服务器构建）**：构建完成后目录已在服务器上，直接进行站点配置。

> 出于安全，仓库的 `.gitignore` 不提交构建产物；请确保上传内容里**包含** `vendor/` 与 `public/assets/`、`public/index.html`。

## 第 4 步 · 创建站点

宝塔左侧 **网站 → 添加站点**：

| 表单项 | 填写 |
| --- | --- |
| 域名 | 你的域名（需先解析 A 记录到服务器 IP）；没有域名就填服务器 IP |
| 根目录 | `/www/wwwroot/Linc-Admin-Dev` |
| PHP 版本 | 8.1 |
| 数据库 | 不勾选（稍后用安装向导创建） |

创建后进入 **站点设置 → 网站目录**：

> ⚠️ **新手最常见的一步坑**：除了运行目录，还必须配置**伪静态**，否则安装向导会提示「后端接口不可达（HTTP 404）」。方法：站点设置 → **伪静态** → 下拉选择 `laravel5` 模板 → 保存。没做这一步，页面能打开但所有接口都是 404。

1. **运行目录**选 `/public`，保存；这一步是安全关键——让 Web 只暴露 `public/`；
2. **伪静态**：下拉选 `laravel5` 模板保存即可（它就是「静态资源优先、其余转 index.php」）。

> 非宝塔用户：按《06 配置与部署》§6.4 的 Nginx 配置照抄（把 `server_name` 与 `root` 换成你的）。

## 第 5 步 · 运行安装向导

1. 浏览器打开 `http://你的域名`（或 IP）：
   - 看到灵枢中控**安装向导**即成功；如果显示 404/空白，回到第 4 步检查运行目录与伪静态；
2. **第一步 环境检查**：全部通过点「下一步」；有不通过项按提示处理（通常是目录权限：把 `runtime/` 和 `config/` 权限改为 755，或 `chown -R www:www`）；
3. **第二步 数据库连接**：

   | 表单 | 填写 |
   | --- | --- |
   | 数据库地址 | `localhost`（MySQL 与网站同机） |
   | 端口 | `3306` |
   | 数据库名 | 自定义，如 `linc_admin`（不存在可勾选「自动创建」） |
   | 账号 / 密码 | MySQL 账号（建议在宝塔「数据库」里建专属库+账号，权限更小更安全） |
   | 会话时区 | 国内保持 `+08:00` |

   点「测试连接」，提示连接成功后进入下一步；
4. **第三步 管理员账号**：设置登录后台的账号与密码（默认 `admin / admin123`，**生产环境务必改强密码**）；存储方式保持「文件存储」即可（无需 Redis）；
5. **第四步 执行安装**：几秒完成 → 点「进入登录页」。

## 第 6 步 · 登录与初始化

1. 用安装时设置的账号登录；
2. 默认「灵枢青」主题（DevUI 风格）；「主题中心」可切换珍珠玻璃，浅色 / 深色在顶栏「外观设置」；
3. 建议**立即做三件事**：修改密码、停用演示账号（`chensy` / `wumin`）、检查参数 `sys.user.initPassword`。

## 第 7 步 · 上线加固（生产环境必读）

| 事项 | 做法 |
| --- | --- |
| HTTPS | 宝塔 **网站 → 设置 → SSL**：Let's Encrypt 一键申请，开启「强制 HTTPS」 |
| 数据库备份 | 宝塔 **计划任务**：每天备份数据库 + 网站，保留 7 天 |
| 面板与端口安全 | 修改宝塔面板端口与入口路径；安全组只放行 80/443 |
| 验证安装锁 | 确认 `runtime/install.lock` 存在；不要删除它（否则安装接口重新暴露） |
| 会话安全 | 多机部署或重启频繁时，把 `config/config.php` 的 `cache.driver` 改为 `redis` |

## 第 8 步 · 本地开发循环

二次开发的日常循环（详见《05 扩展开发实战》）：

```bash
# 终端 1：后端（PHP 内置服务器）
php -S 127.0.0.1:8090 -t public public/index.php

# 终端 2：前端热更新（Vite 代理 /api → 8090）
cd frontend && npm run dev

# 发布：构建并部署前端
cd frontend && npm run build && cp -r dist/* ../public/

# 回归：37 项契约断言
php tests/api_contract.php http://127.0.0.1:8090
```

## 常见安装问题速查

| 现象 | 处理 |
| --- | --- |
| 安装向导提示「后端接口不可达（HTTP 404）」 | 伪静态未配置：站点设置 → 伪静态 → 选 `laravel5` 保存后刷新 |
| 页面样式丢失 / 刷新 404 | 忘了构建前端或没把 `dist/` 拷进 `public/`；运行目录不是 `public/`；伪静态未配置 |
| 报错找不到 vendor/ | 没执行 `composer install`（本版本不内置依赖） |
| 安装向导说目录不可写 | 改 `runtime/`、`config/` 权限为 755，属主改为 PHP 进程用户 |
| 「数据库连接失败」 | 账号密码错误；或 MySQL 未启动；远程库需放行来源 IP |
| 装完想换库 | 删除 `runtime/install.lock` 与 `config/config.php`，刷新重装 |

更多问题见《09 常见问题 FAQ》；部署细节（Nginx 手写配置、Redis、多机）见《06 配置与部署》。
