# 04 · 开发规范

> 本规范是灵枢中控的默认约定。遵循它，你的模块会自动获得权限、审计、分页、导出与主题能力；偏离时请在代码注释中说明原因。

## 4.1 后端规范

### 4.1.1 分层与命名

```
app/Controller/XxxController.php      类名与资源对应（UserController）
app/Service/XxxService.php            业务规则唯一归属地
app/Repository/XxxRepository.php      SQL 唯一归属地，静态方法 + PDO 预处理
```

- 命名空间 `Linc\`；PHP ≥ 8.0 语法（构造器属性提升、`match`、`readonly`）；
- 方法命名与 Java 版语义对齐：`selectXxx / countXxx / insertXxx / updateXxx / softDeleteXxx`；
- 一张业务表一对 Service / Repository；跨表事务放在 Service，`Database::beginTransaction() / commit() / rollBack()`。

### 4.1.2 接口规范

- 路径：`/api/<模块>/<资源>`，REST 语义（GET 查 / POST 增 / PUT 改 / DELETE 删）；路径参数 `{id}` 必须 `AuthController::pathId()` 转换（非数字 → `参数类型错误: id`）；
- 响应：一律 `R::success($data)` 包络；业务失败 `throw new BusinessException('中文文案')`，HTTP 状态由异常处理器统一映射；
- 分页：入参 `PageQuery::fromQuery()`，出参 `PageResult::of()`；pageSize 上限 100；
- 新路由必须在 `AppFactory::registerRoutes()` 登记，并**同时**标注权限与写操作日志：

```php
$group->post('/contracts', [ContractController::class, 'create'])
    ->add(new OperLog('合同管理', '新增'))
    ->add(new RequirePermission('biz:contract:add'));
```

### 4.1.3 数据规范

- 业务表默认含四个审计字段：`create_by VARCHAR(64)`、`update_by VARCHAR(64)`、`create_time DATETIME`、`update_time DATETIME`（日志表、关联中间表可例外，需说明）；
- 逻辑删除用 `deleted TINYINT`（0 正常 / 1 删除），查询一律带 `deleted = 0`；唯一索引与软删除并存的边界见《09 FAQ》；
- 字段写入用 COALESCE 部分更新（`SET name = COALESCE(?, name)`），`null` 表示不改；
- 返回给前端的英文字段（接口、数据库、权限码）必须在注释或文档中附中文含义；
- 时间统一交给数据库时钟（`NOW()` / `DATE_FORMAT`），不要用 PHP 时间拼 SQL 条件。

### 4.1.4 安全规范

- 一切 SQL 走 PDO 预处理，禁止字符串拼接值；
- 新增写接口必须挂 `RequirePermission`；不公开的数据接口禁止加入 `AuthMiddleware::PUBLIC_PATHS`；
- 敏感字段（password / token / secret）不落日志明文——`OperLog` 已自动打码，自定义日志请遵循同一规则；
- 密码只存 BCrypt；`sys_config` 中的初始密码参数（`sys.user.initPassword`）仅用于重置场景。

## 4.2 前端规范

### 4.2.1 组件与复用优先级

1. 已有通用组件能满足 → 直接复用（`ListPage`、`FormDialog`、`DataTable`、`PermissionButton`、`PageHeader`、`SectionLabel`…）；
2. 稍有不足 → 扩展通用组件，而不是页面内特判；
3. 多页面用到的新能力 → 沉淀为 `composables/` 或 `components/`；
4. 单页面独有逻辑 → 才写在页面内。

### 4.2.2 页面结构

- 页面骨架：`PageHeader`（标题 + 描述）→ 查询区 → 内容面板；列表页直接用 `ListPage`（自带查询 / 重置 / 分页 / 导出 / 勾选 / 底部浮条）；
- 新页面必须在 `composables/auth.ts` 的 `COMPONENT_MAP` 登记组件映射，并配套菜单 SQL（`sys_menu` + 超管授权）；
- 路由路径由菜单数据驱动，页面不要自行 `router.addRoute`。

### 4.2.3 样式与主题

- **只引用设计令牌**（`tokens.css`），禁止在页面手写颜色 / 圆角 / 阴影字面量——这是多主题的前提；
- 页面差异样式写入 `styles/pages.css` 对应区块，组件差异写入所属层，禁止新建随意命名的新样式文件；
- 动效统一走 `composables/motion.ts` 的 GSAP 入口；新动效必须尊重 `skipMotion()`（减少动效偏好）；
- 图标：使用 `data/icons.ts` 已登记的线性图标；新图标以 24 网格 / 1.6 描边 / 圆头路径绘制。

### 4.2.4 接口层

- 页面不直接 `fetch`：一律经 `api/http.ts` 的 `httpClient`（自动包络解包、401 处理、追踪 ID）；
- 每个后端模块对应 `src/api/` 下一个文件，导出类型化的方法集合；
- 下载（CSV / ZIP）用 `httpClient.download()`，走 Blob。

## 4.3 文档与变更

- 代码变更同步 `changelog.md`；接口 / 表结构 / 调用链变化同步 `docs/02`、`docs/03`；
- 不主动提交版本库；完成一个逻辑单元后给出建议的 commit message 待确认；
- 提交前跑一遍回归：`php tests/api_contract.php` + 前端 `npm run build`（含 `vue-tsc` 类型检查）。
