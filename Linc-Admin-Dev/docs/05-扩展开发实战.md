# 05 · 扩展开发实战

本章用两个完整实战覆盖最常用的二次开发路径：**§5.1 新增一个业务模块**（后端 + 前端 + 权限 + 菜单）、**§5.2 开发一套主题**（多主题体系的核心玩法）。跟随操作即可产出可交付的代码。

## 5.1 实战一：新增业务模块（以「公告管理 notice」为例）

### 第 1 步：设计数据表

```sql
CREATE TABLE IF NOT EXISTS biz_notice (
    id BIGINT NOT NULL AUTO_INCREMENT COMMENT '公告 ID',
    title VARCHAR(200) NOT NULL COMMENT '公告标题',
    content TEXT COMMENT '公告内容',
    status TINYINT NOT NULL DEFAULT 1 COMMENT '状态：1 发布，0 草稿',
    create_by VARCHAR(64) DEFAULT NULL COMMENT '创建人',
    update_by VARCHAR(64) DEFAULT NULL COMMENT '更新人',
    create_time DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    PRIMARY KEY (id),
    KEY idx_biz_notice_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='公告表';
```

规范要点：审计四字段、逻辑删除（如需要加 `deleted`）、字段注释写清中文含义。把脚本放入 `database/V4__biz_notice.sql`（版本号递增，安装器自动执行，幂等）。

### 第 2 步：仓储层（SQL 唯一归属地）

新建 `app/Repository/NoticeRepository.php`：

```php
<?php
declare(strict_types=1);

namespace Linc\Repository;

use Linc\Core\Database;

final class NoticeRepository
{
    private const BASE = "FROM biz_notice WHERE deleted = 0";

    public static function count(?string $keyword, ?int $status): int
    {
        return (int) Database::scalar(
            "SELECT COUNT(*) " . self::BASE .
            " AND (? IS NULL OR ? = '' OR title LIKE CONCAT('%', ?, '%'))" .
            " AND (? IS NULL OR status = ?)",
            [$keyword, $keyword, $keyword, $status, $status]
        );
    }

    public static function select(?string $keyword, ?int $status, int $offset, int $pageSize): array
    {
        return Database::all(
            "SELECT id, title, content, status,
                    DATE_FORMAT(create_time, '%Y-%m-%d %H:%i') AS createTime " . self::BASE .
            " AND (? IS NULL OR ? = '' OR title LIKE CONCAT('%', ?, '%'))" .
            " AND (? IS NULL OR status = ?)
             ORDER BY id DESC LIMIT ?, ?",
            [$keyword, $keyword, $keyword, $status, $status, $offset, $pageSize]
        );
    }

    public static function insert(array $row, string $operator): int
    {
        return Database::insert(
            "INSERT INTO biz_notice (title, content, status, create_by, update_by)
             VALUES (?, ?, ?, ?, ?)",
            [$row['title'], $row['content'], $row['status'], $operator, $operator]
        );
    }

    public static function softDelete(int $id, string $operator): int
    {
        return Database::execute(
            "UPDATE biz_notice SET deleted = 1, update_by = ? WHERE id = ? AND deleted = 0",
            [$operator, $id]
        );
    }
}
```

### 第 3 步：服务层（校验与规则）

新建 `app/Service/NoticeService.php`：

```php
<?php
declare(strict_types=1);

namespace Linc\Service;

use Linc\Core\AuthContext;
use Linc\Core\BusinessException;
use Linc\Core\PageQuery;
use Linc\Core\PageResult;
use Linc\Repository\NoticeRepository;

final class NoticeService
{
    public static function page(PageQuery $query, ?string $keyword, ?int $status): array
    {
        $pageNum = $query->normalizedPageNum();
        $pageSize = $query->normalizedPageSize();
        return PageResult::of(
            NoticeRepository::select($keyword, $status, ($pageNum - 1) * $pageSize, $pageSize),
            NoticeRepository::count($keyword, $status),
            $pageNum,
            $pageSize
        );
    }

    public static function create(array $request): array
    {
        $title = required(isset($request['title']) && is_string($request['title']) ? $request['title'] : null, '公告标题不能为空');
        $id = NoticeRepository::insert([
            'title' => $title,
            'content' => self::stringOrNull($request['content'] ?? null),
            'status' => default_int(isset($request['status']) ? (int) $request['status'] : null, 1),
        ], AuthContext::operator());
        return ['id' => $id];
    }

    public static function remove(int $id): void
    {
        if (NoticeRepository::softDelete($id, AuthContext::operator()) === 0) {
            throw new BusinessException('公告不存在或已删除');
        }
    }

    private static function stringOrNull(mixed $value): ?string
    {
        return is_scalar($value) ? (string) $value : null;
    }
}
```

### 第 4 步：控制器 + 路由（权限与审计一次到位）

新建 `app/Controller/NoticeController.php`：

```php
<?php
declare(strict_types=1);

namespace Linc\Controller;

use Linc\Service\NoticeService;
use Psr\Http\Message\ResponseInterface as Response;
use Psr\Http\Message\ServerRequestInterface as Request;

final class NoticeController
{
    public function index(Request $request, Response $response): Response
    {
        $q = $request->getQueryParams();
        $keyword = is_string($q['keyword'] ?? null) && $q['keyword'] !== '' ? $q['keyword'] : null;
        $status = is_numeric($q['status'] ?? null) ? (int) $q['status'] : null;
        return AuthController::ok($response, NoticeService::page(AuthController::pageQuery($request), $keyword, $status));
    }

    public function create(Request $request, Response $response): Response
    {
        return AuthController::ok($response, NoticeService::create(json_body((string) $request->getBody())));
    }

    public function remove(Request $request, Response $response, array $args): Response
    {
        NoticeService::remove(AuthController::pathId($args));
        return AuthController::ok($response);
    }
}
```

在 `AppFactory::registerRoutes()` 登记（权限码 `biz:notice:*`，写接口挂操作日志）：

```php
$app->group('/api/biz/notice', function (RouteCollectorProxy $group): void {
    $group->get('', [NoticeController::class, 'index']);
    $group->post('', [NoticeController::class, 'create'])
        ->add(new OperLog('公告管理', '新增'));
    $group->delete('/{id}', [NoticeController::class, 'remove'])
        ->add(new OperLog('公告管理', '删除'));
})->add(new RequirePermission('biz:notice:list'));
```

> 需要数据权限时：在查询 WHERE 中接入 `DataScopeService::current()` + `scopeClause()` 模式（参考 `SystemManagementRepository::userWhere()`），并在路由组上应用 `new DataScope()` 等价逻辑——用户与部门字段命名保持 `create_by` / `dept_id` 即可自动获得五种数据范围。

## 5.2 实战二：主题开发（多主题体系）

### 5.2.1 主题架构一览

灵枢中控的皮肤主题 = **CSS 设计令牌覆盖包**。全站颜色、圆角、阴影、材质只来自 `frontend/src/styles/tokens.css` 的设计令牌，组件永远只引用令牌，因此：

```
<html data-skin="linc" data-theme="dark" data-density="regular">
          │                │              └─ 表格密度（宽松/标准/紧凑）
          │                └─ 浅色 / 深色（跟随系统可自动切换）
          └─ 主题包（SKINS 注册表 + styles/themes/<key>.css 令牌覆盖）
```

三层各司其职、自由组合：**2 个主题包 × 2 种明暗 × 3 种密度 = 12 种外观**，而业务页面代码为零份拷贝。

### 5.2.2 内置主题

| key | 名称 | 风格 | 说明 |
| --- | --- | --- | --- |
| `linc` | 灵枢青 | 复刻 DevUI 设计语言 | **出厂默认**。靛蓝主色 `#5e7ce0`、冷灰画布、纯白面板、小圆角（4-12px）、轻阴影、扁平材质；深色为 DevUI 暗色面板系 |
| `pearl` | 珍珠玻璃 | 玻璃拟态 | 经典主题。柔和灰绿画布、玻璃浮层与仪器化语汇、青柠点缀；基线令牌即珍珠玻璃，无覆盖文件 |

### 5.2.3 开发一套新主题（约 30 分钟）

以做一套「灵枢墨」（深色优先的墨绿金主题）为例，四步完成：

**① 创建令牌覆盖文件** `frontend/src/styles/themes/ink.css`：

```css
/* 灵枢墨：深色优先主题。浅色档也要提供（跟随系统/浅色模式使用） */
:root[data-skin="ink"] {
  --ink: #2b2f27;
  --ink-muted: #5c6157;
  --blue: #3f7d5a;          /* 主色：墨绿 */
  --blue-hover: #4f9068;
  --blue-soft: rgba(63, 125, 90, .12);
  --stage: #e7e9e2;         /* 画布底 */
  --canvas: #f4f6f1;
  --rail-bg: rgba(255, 255, 255, .98);
  --r-md: 10px;             /* 圆角档位可整体调整 */
  /* …其余令牌按需覆盖；未覆盖的回退 tokens.css 基线… */
}

:root[data-skin="ink"][data-theme="dark"] {
  --ink: #e8ebe4;
  --blue: #7db894;
  --stage: #0e100d;
  --canvas: #151813;
  --surface-solid: #1d201b;
  /* … */
}
```

要点：

- 选择器**必须**是 `:root[data-skin="<key>"]` 与 `:root[data-skin="<key>"][data-theme="dark"]`（明暗组合）；
- 只覆盖需要调整的令牌，其余自动回退基线——新令牌天然兼容；
- 颜色之外可调：圆角五档（`--r-xs` ~ `--r-xl`）、阴影三档（`--e1` ~ `--e3`）、材质（`--pill-bg` / `--surface` / `--float-bg`…）、图谱 RGB 三元组（`--graph-*`，Canvas 使用）。

**② 注册元数据**（`frontend/src/themes/index.ts`）：

```ts
{
  key: 'ink',
  name: '灵枢墨',
  tagline: '墨绿金 · 沉稳内敛',
  version: '1.0.0',
  author: '你的名字',
  description: '一句话介绍风格与适用场景。',
  tags: ['新主题', '墨绿'],
  preview: { primary: '#3f7d5a', canvas: '#f4f6f1', surface: '#ffffff', rail: '#ffffff', accent2: '#c9a34e' },
},
```

`preview` 色卡驱动主题中心卡片的迷你预览图，务必与令牌取值一致。

**③ 引入样式**（`frontend/src/main.ts`）：

```ts
import './styles/themes/ink.css'
```

**④ 构建 → 主题中心即见**：

```bash
cd frontend && npm run build && cp -r dist/* ../public/   # Windows 同义操作
```

打开「主题中心」，新卡片已出现，点击即换、刷新后保持（localStorage `linc.appearance.skin`）。

### 5.2.4 主题设计检查清单

- [ ] 浅色 / 深色两档都提供，暗色下 `--ink` 五档与背景对比度达标（正文 ≥ 4.5:1）；
- [ ] `--blue` 与 `--blue-hover` 有可感知的悬停反馈；`--focus` 可见（键盘可达性）；
- [ ] 状态色语义不反转：蓝 = 选择/主操作、绿 = 正常、红 = 危险；
- [ ] 图谱 Canvas 的 `--graph-*` RGB 三元组与分类色一致，否则关系图会"断色"；
- [ ] 预览色卡 `preview` 与真实令牌一致；
- [ ] 在工作台、用户列表（表格密度三档）、登录页四类页面各过一遍浅色与深色。

### 5.2.5 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 切换后部分区域颜色不变 | 该处样式写死了字面量——按《04》规范改回令牌引用 |
| 新主题不出现在主题中心 | `SKINS` 未登记或 `main.ts` 未引入 CSS；检查 key 拼写 |
| 深色下玻璃边框刺眼 | 覆盖 `--glass-line` / `--edge`（珍珠玻璃基线的白色高光需要压暗） |
| 想让某主题默认不提供深色 | 不建议；若必须，暗色档回退基线即可，明暗开关仍由用户控制 |
