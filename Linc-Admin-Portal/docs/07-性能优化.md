# 07 · 性能优化

灵枢中控默认配置即面向中小规模后台（几十万级日志、千级账号）优化。本章按「先测量、后优化」给出路径。

## 7.1 数据库层（收益最大）

### 索引

建表脚本已为高频查询建索引：`sys_user(dept_id, status)`、`sys_menu(permission)`、日志表时间与操作人。新增业务表时遵循同样原则：

- 所有 `WHERE` 高频列建索引；`LIKE '%kw%'` 无法走索引——日志关键词检索量大时改用全文索引或接入搜索引擎；
- 联表聚合（用户列表的岗位 / 角色聚合）已用 `GROUP_CONCAT + GROUP BY u.id`，数据量大时可为 `sys_user_post(user_id)`、`sys_user_role(user_id)` 覆盖索引（复合主键已覆盖）；
- 部门子树查询 `FIND_IN_SET(deptId, ancestors)` 依赖 `ancestors` 链，深层级大部门可改物化路径表。

### 慢查询排查

```sql
-- 开启慢日志（my.cnf）
slow_query_log = ON
long_query_time = 0.5
-- EXPLAIN 检查 rows 与 type
EXPLAIN SELECT COUNT(DISTINCT u.id) FROM sys_user u LEFT JOIN sys_dept d ON d.id = u.dept_id WHERE ...;
```

## 7.2 分页与导出

- 列表一律 `LIMIT offset, size` 且 pageSize 上限 100；深分页（第 1000 页）建议改「游标分页」（`WHERE id < ? ORDER BY id DESC LIMIT 20`）；
- 导出统一上限 5000 行（与经典实现一致）；更大导出改为异步任务落文件（`sys_file` 表已预留）。

## 7.3 缓存

| 热点 | 现状 | 优化建议 |
| --- | --- | --- |
| token / 验证码 | 文件缓存（flock） | 高并发或多机切 Redis（`cache.driver=redis`） |
| 权限码集合 | 每请求实时查库 | 读多写少，可在 `PermissionService` 增加 60 秒进程内缓存（注意改权限后失效） |
| 字典选项 | 每请求查库 | 低频变更，可加进程内缓存；前端已有会话级缓存 |
| 工作台统计 | 实时聚合 | 日志量大时改为分钟级定时汇总表 |

> 令牌存储的 TTL 与键名语义在文件 / Redis 两种驱动间完全一致，切换零业务影响。

## 7.4 PHP 进程

- 生产使用 **PHP-FPM**：`pm = dynamic`，`pm.max_children` 按内存估算（单进程 ~30-50MB）；
- 开启 OPcache（默认开启）：`opcache.validate_timestamps=1` + `revalidate_freq=60`，发布后 `opcache_reset()`；
- `realpath_cache_size=4096k`（框架文件多）。

## 7.5 前端加载

- 构建产物已按路由分包（每个页面独立 chunk，GSAP 在首屏包外按需加载）；Nginx 开启 gzip（gzip 已默认压缩，CSS ~24KB gzip）：
  ```nginx
  gzip on;
  gzip_types text/css application/javascript application/json image/svg+xml;
  gzip_min_length 1k;
  ```
- 静态资源文件名带内容 hash，可设长缓存：
  ```nginx
  location /assets/ { expires 30d; add_header Cache-Control "public, immutable"; }
  ```
- `index.html` 不缓存（保证发版即生效）；
- 大表格开启虚拟滚动前先确认数据量（组件默认已做请求序号防乱序，分页即可满足多数场景）。

## 7.6 图表与动效

- 工作台 / 监控图表为自绘 SVG / Canvas，无第三方图表库运行时开销；
- 动效统一 GSAP；系统检测 `prefers-reduced-motion` 与后台标签页自动降级（`skipMotion()`），不会出现后台标签页动画堆积；
- 登录页神经网络背景仅在登录页运行，进入外壳即销毁。

## 7.7 压测参考路径

```bash
# 只测认证开销（缓存命中）
ab -n 2000 -c 50 -H "Authorization: Bearer <token>" http://127.0.0.1:8090/api/system/dict/options/sys_user_sex
```

典型结论：文件缓存下单接口 P95 < 10ms（本机、命中令牌存储），瓶颈通常在 MySQL；优化顺序永远是「索引 → SQL → 缓存 → 进程」。
